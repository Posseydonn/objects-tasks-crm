# Проверка миграций

Из корня репозитория (Node.js 24):

```sh
npm ci --prefix supabase/tests
npm test --prefix supabase/tests
```

Тест создаёт две независимые пустые PostgreSQL-базы в памяти через PGlite
0.5.15, применяет **все** SQL-файлы из migrations в порядке версий и затем
проверяет права и цикл статусов (26 проверок). Первая база не содержит
необязательную платформенную функцию `public.rls_auto_enable()`. Во второй
создана её event-trigger заглушка; проверяется отзыв прав anon/authenticated.
Для обеих баз минимальные auth.users/auth.uid и роли Supabase создаются
тестовой обвязкой. Это проверка PostgreSQL SQL, а не полный Supabase/Docker
reset или запуск веб-интерфейса. Тест не подключается к облаку и не читает
пароли. Дополнительные зависимости изолированы от основного приложения.

## История облака

Локальные версии совпадают с `supabase_migrations.schema_migrations`:

| Версия | Имя |
| --- | --- |
| 20261104201811 | crm_initial |
| 20261104201920 | restrict_internal_rls_trigger |

Версии локальных файлов приведены к уже существующим облачным записям.
Облачная схема и её история не переприменялись и не очищались. Тело второй
локальной миграции получило проверку наличия необязательной функции для новых
установок; в существующем облаке отзыв прав уже выполнен и проверен.

## Проверки облачного API

`hosted-security.mjs` использует реальные пользовательские сессии и создаёт
демоданные. Запускать только на подготовленной пустой прикладной базе с
тестовыми профилями, не повторять на текущей демонстрационной базе.
`hosted-followup.ps1` изменяет существующий объект и metadata, пробует запрещённые записи и удаление. При регрессии защиты он может повредить демоданные. Запускать только на изолированной тестовой базе; на текущей демобазе не повторять.
Оба читают локальные `.env.local` и `.crm-test-access.json.local`; эти файлы
не публикуются. Формат доступа: `accounts` — массив двух постановщиков,
затем двух исполнителей, каждый с `email` и `password`.
Для Node HTTP при необходимости задайте HTTPS_PROXY и --use-env-proxy;
PowerShell-скрипт использует локальный прокси 127.0.0.1:7897.

Сохранённые результаты реальных API-проверок: docs/database-verification.json.
Свежий локальный replay не переобъявляет эти старые API-проверки как новые.
