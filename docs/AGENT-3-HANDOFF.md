## Подключение

В `src/App.tsx` заменить StagePlaceholder следующими именованными экспортами:

| Маршрут | Импорт | Компонент |
|---|---|---|
| `/objects` | `./pages/ObjectsPage` | `ObjectsPage` |
| `/objects/:objectId` | `./pages/ObjectPage` | `ObjectPage` |
| `/tasks/:taskId` | `./pages/TaskPage` | `TaskPage` |
| `/my-tasks` | `./pages/MyTasksPage` | `MyTasksPage` |

Параметры совпадают с зарезервированными маршрутами. Компоненты используют существующие AuthProvider, Ant Design App, Router и типизированный Supabase-клиент. CSS автоматически импортируется через `src/pages/crm/shared.tsx`. Дополнительные зависимости, env и изменения контракта не нужны.

## Поведение

- Список объектов с поиском по названию/адресу, создание объекта постановщиком.
- Карточка объекта: адрес, задачи со статусами/исполнителями, редактирование, подтверждение мягкого удаления, создание задачи.
- Карточка задачи: все поля, имя автора, дата, история с именами/временем/комментариями; только допустимые текущей роли и статусу кнопки.
- Формы задачи: название, описание, объект, исполнитель; редактирование позволяет перенос и переназначение, статус не отправляется.
- Возврат требует содержательного комментария. Пустые/пробельные обязательные поля запрещены формами и БД.
- «Мои задачи»: назначенные текущему пользователю задачи, поиск и фильтр статуса. Постановщику показывается пояснение и пустой список, без чужих задач в этом разделе.
- Запись — существующий `api` с RPC. Чтение — локальный адаптер `screenReads(signal)` в участке агента 3: те же таблицы/фильтры контракта, но с `abortSignal`, которого нет в общем API. Роль читается из profiles. При смене маршрута, обновлении и размонтировании запросы отменяются; устаревшие ответы дополнительно игнорируются.
- После записи данные перечитываются. Повторная отправка блокируется; ошибки отображаются по-русски, введённые данные при ошибке формы сохраняются.
- Таблицы прокручиваются внутри контейнера, панели карточки задачи складываются в одну колонку.
