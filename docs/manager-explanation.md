# Как устроена CRM

В системе есть строительные объекты и задачи по каждому из них. Руководитель входит под своей учётной записью, создаёт объект с названием и адресом, описывает задачу и назначает исполнителя. В карточке сразу видно, кто отвечает за работу и на каком этапе она находится. Постановщиков и исполнителей может быть несколько.

Исполнитель видит только назначенные ему задачи и те объекты, где есть его работа. Он берёт новую задачу в работу, а после выполнения отправляет её на проверку. Руководитель принимает результат или возвращает задачу на доработку. При возврате обязательно объясняет, что исправить. После исправлений исполнитель снова передаёт результат на проверку. Самостоятельно принять свою работу или перескочить через этап исполнитель не может.

В карточке хранится история: кто и когда изменил статус, каким был предыдущий этап и какой стал следующим. Комментарий руководителя остаётся рядом с возвратом. Поэтому участникам не нужно восстанавливать последовательность действий по переписке.

Ограничения действуют в самой базе данных — месте, где хранятся записи. Скрытые кнопки лишь упрощают интерфейс. Если исполнитель попробует отправить запрос напрямую, база всё равно не отдаст чужую задачу и не разрешит её изменить. Историю нельзя самостоятельно дописать, исправить или удалить через обычный доступ приложения. Новый статус и запись о нём сохраняются вместе: задача не должна сменить этап без следа в истории.

Свободной регистрации нет: пользователей и роли назначает администратор. При переназначении старый исполнитель теряет доступ, а новый получает задачу с её историей. Удаление скрывает запись из рабочих экранов, сохраняя историю; отдельного архива в этой версии нет. Это небольшая демонстрационная CRM: резервное копирование, эксплуатационный мониторинг и организация доступа для реальной компании требуют отдельной настройки.
