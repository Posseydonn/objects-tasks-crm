## Сетевые и проверочные сбои

Прямое соединение с Vercel обрывалось на TLS; после включения пользователем прокси публикация прошла. Supabase периодически возвращает ERR_CONNECTION_CLOSED: чтения и безопасное повторное сохранение проверялись после фактического перечитывания данных. Начальные локаторы проверки не учитывали звёздочку обязательного поля; исправлен проверочный сценарий, приложение по этому поводу не менялось.

## Свежая браузерная приёмка на опубликованной версии

Проверены настоящие пользовательские сессии; API не подменялся. Применялся Playwright CLI. Локальные сценарии и логи содержат доступы и исключены из Git; в отчёт внесены только результаты.

- Постановщик создал отдельный временный объект, изменил адрес и создал задачу с описанием и назначением Олегу. Начальная история, автор, дата и поля видны в карточке.
- Изменил описание и переназначил задачу Марии. После сетевого отказа сохранение повторено; карточка перечитана, изменения подтверждены.
- При выходе и входе Олегом в том же окне старая карточка не сохранилась. Прямая ссылка недоступна, в «Моих задачах» переназначенной задачи нет.
- Мария увидела задачу в «Моих задачах» и историю. Кнопки редактирования нет. Прошла «Новая → В работе → На проверке».
- Постановщик попробовал вернуть задачу с пробелами: форма потребовала содержательный комментарий. Возврат с текстом «Уточнить результат приёмки» сохранён и отображён в истории.
- Мария продолжила работу и снова отправила результат. Постановщик принял задачу.
- Перезагрузка прямой ссылки сохранила сессию и открыла принятую задачу. В Timeline ровно семь записей: создание и шесть переходов. [Снимок](final-accepted-task.png) просмотрен визуально.
- Постановщик удалил задачу через подтверждение. Прямая ссылка стала недоступна.
- В том же временном объекте создана отдельная дочерняя задача; затем объект удалён через подтверждение. Прямые ссылки на объект и дочернюю задачу недоступны.
- Перед началом сохранены JSON активных объектов, задач и доступной постановщику истории; после очистки они перечитаны со стабильной сортировкой и полностью совпали. Сохранены все четыре объекта, присутствовавшие перед проверкой, включая пользовательский `JJJ`, и исходные задачи/история. Новые проверочные записи только мягко удалены; база не очищалась.
- Выполнен выход из проверочной сессии.
- Для обоих исполнителей отдельно сопоставлены результаты REST-чтения с выборкой постановщика: каждый получает только свои задачи, а объекты — только при наличии своей задачи. Чужая задача и её история возвращают пустой набор. Прямой переход в чужой объект показывает «Недоступна или не найдена». В общем объекте ссылок на чужие задачи нет.

Это приёмка демонстрационного приложения, а не утверждение о готовности к эксплуатации с реальными данными. Проверка выше проходила на основном alias после публикации исправлений; полный прошлый набор hosted-негативных запросов и конкуренция повторно не запускались.

## Вердикт

Обязательных функциональных дефектов по завершённой приёмке не осталось. Тестовое можно сдавать: приложение опубликовано, репозиторий доступен анонимно, миграции и четыре составляющие сдачи подготовлены. Перед отправкой пользователь добавляет три действующих доступа непосредственно в hh.ru; паролей в черновике нет. Сообщение не отправлялось.

Не закрыты как эксплуатационные задачи: оптимизация большого JS-пакета, серверная пагинация экранов для больших объёмов, мониторинг и резервирование. Сетевые обрывы локального прокси мешали проверке, повторные действия подтверждены перечитыванием; длительная стабильность сети и сервисов не доказана. Понимание кода пользователем нужно проверить перед созвоном по demo-guide.md. Количество исходных объектов в текущей базе — четыре из-за дополнительной пользовательской записи; она намеренно сохранена, хотя ТЗ предлагает 2–3 демонстрационных объекта.
