# Демонстрация и подготовка к созвону

## Сценарий на 5 минут

1. Войти постановщиком. Показать объекты, поля задачи и разные статусы.
2. Создать отдельный временный объект и задачу для первого исполнителя. Показать автора, дату и начальную историю.
3. Выйти и войти вторым исполнителем в том же окне: чужая задача по ссылке недоступна. Войти назначенным исполнителем: задача есть в «Моих задачах», редактирования нет.
4. Взять в работу и отправить на проверку. Под постановщиком вернуть с комментарием, затем повторить работу и проверку, принять.
5. Показать историю из семи записей и сохранённый комментарий. Удалить временные записи постановщиком, исходное демо не менять.

При сетевой ошибке не выдавать сохранение за успешное: сначала обновить карточку и проверить фактический результат. Создание при потерянном ответе нельзя бездумно повторять — сначала проверить список.

## Что объяснить по коду

- `src/auth/AuthProvider.tsx`: Supabase хранит сессию, приложение реагирует на вход/выход. `App.tsx` защищает маршруты и пересоздаёт экраны при смене пользователя.
- `src/pages/TaskPage.tsx`: кнопки зависят от роли, назначения и статуса. Это удобство интерфейса; окончательное решение принимает база.
- `src/lib/api.ts`: чтение с отменой запросов, запись через RPC. `readAll.ts` собирает страницы и не выдаёт частичный результат при сбое поздней страницы.
- `supabase/migrations/20261104201811_crm_initial.sql`: RLS ограничивает чтение; RPC проверяет роль и переход. Публичный ключ обозначает приложение, но не заменяет сессию пользователя и не отменяет RLS.
- `change_task_status`: блокировка строки предотвращает два несовместимых перехода. Обновление статуса и вставка истории выполняются в одной транзакции: обе операции проходят вместе либо откатываются.
- У исполнителя нет прямого права записи истории и изменения профиля. Самостоятельно назначить себе роль постановщика он не может.
- `supabase/tests/local-security.mjs`: пример отрицательной проверки прямой записи и полного цикла. Локальный SQL-тест не заменяет настоящий вход и проверку опубликованного интерфейса.

Пользователю нужно самостоятельно пройти этот сценарий и объяснить перечисленные места. Наличие инструкции ещё не подтверждает понимание кода.
