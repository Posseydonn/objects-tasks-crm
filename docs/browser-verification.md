# Воспроизводимая браузерная приёмка

`tests/browser-acceptance.mjs` использует настоящий браузер, Auth и базу без подмены API. Секреты читаются во время запуска. Скрипт не пишет скриншоты, HAR, trace, пароли или сырые ошибки Playwright. Локальный файл доступов игнорируется Git. Не включайте диагностическое логирование Playwright при вводе паролей.

## Подготовка

```sh
npm ci
npx playwright install chromium
```

Создайте **локальный** `.crm-test-access.json.local` со структурой ниже. Значения заменяются настоящими доступами; в репозиторий файл не добавляется. `id` совпадает с UUID Auth и profiles, `full_name` — с именем в profiles.

```json
{"accounts":[
  {"email":"manager@example.invalid","password":"REPLACE_LOCALLY","role":"manager","id":"UUID","full_name":"Постановщик"},
  {"email":"executor1@example.invalid","password":"REPLACE_LOCALLY","role":"executor","id":"UUID","full_name":"Исполнитель 1"},
  {"email":"executor2@example.invalid","password":"REPLACE_LOCALLY","role":"executor","id":"UUID","full_name":"Исполнитель 2"}
]}
```

В `.env.local` нужны публичные URL и ключ **той же базы**, с которой работает проверяемый сайт. Пароли в env фронтенда не добавляйте. Должны присутствовать назначенные обоим исполнителям задачи; для полной проверки ограничений — чужие задачи и объекты. Во время проверки не редактируйте демо в другом окне.

## Запуск (PowerShell)

Для локального приложения запустите `npm run dev` в отдельном терминале. По умолчанию проверяется `http://127.0.0.1:5173`.

```powershell
node tests/browser-acceptance.mjs
```

Для опубликованного сайта:

```powershell
$env:CRM_BASE_URL='https://objects-tasks-crm-six.vercel.app'
node tests/browser-acceptance.mjs
```

По умолчанию выполняются только входы и чтение: защищённый маршрут, постановщик, два исполнителя, собственные задачи/история, чужие прямые ссылки, мобильное меню. Состояние активных данных сравнивается до и после. Пропущенные условия при отсутствии чужого объекта/задачи не доказывают ограничения доступа: используйте подходящие демоданные.

**Полный сценарий с записью — только на тестовой базе**, с отдельным временным объектом:

```powershell
node tests/browser-acceptance.mjs --write
```

Он дополнительно создаёт и редактирует объект/задачу, переназначает исполнителя, проходит полный цикл с доработкой, проверяет пробельный комментарий, семь записей истории, перезагрузку прямой ссылки и удаление задачи. В `finally` удаляет только свой объект через штатный RPC и сверяет исходные активные записи/историю. Мягко удалённые проверочные записи физически остаются в базе. Скрипт не повторяет запросы записи автоматически: при сетевом сбое завершается с ненулевым кодом и пытается убрать свой объект.

Для просмотра браузера добавьте `--headed`. Для уже установленного Chromium можно задать `CRM_BROWSER_PATH`. Для нестандартного пути к доступам — `CRM_ACCESS_FILE`.

Если нужен прокси, задайте `CRM_PROXY` для браузера, `HTTPS_PROXY` и `NODE_USE_ENV_PROXY=1` для Node.js. Адрес прокси зависит от компьютера; он не зашит в сценарий. Не передавайте пароль прокси в командной строке и отчётах.

Этот сценарий не заменяет прежние отрицательные API-тесты и проверку конкуренции. `hosted-security.mjs` и `hosted-followup.ps1` для этой приёмки не запускаются.
