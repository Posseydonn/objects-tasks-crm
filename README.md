# Мини-CRM «Объекты и задачи»

CRM для строительной компании: постановщики управляют объектами и задачами, исполнители выполняют назначенные задачи. React, TypeScript, Vite, Ant Design и Supabase.

Приложение: https://objects-tasks-crm-six.vercel.app

## Запуск

Требуется Node.js 24 и npm. В корне проекта:

```sh
npm ci
```

Скопируйте `.env.example` в `.env.local`, укажите URL своего Supabase и публичный publishable key. Секретный/service-role ключ во фронтенде не используется.

```sh
npm run dev
npm run build
```

`build` включает проверку TypeScript. Готовые статические файлы находятся в `dist/`. Для Vercel публичные переменные из `.env.example` задаются в настройках проекта перед сборкой. `vercel.json` обеспечивает работу прямых ссылок.

## База и доступ

SQL-миграции — `supabase/migrations/`. Воспроизведение схемы и проверки описаны в [supabase/tests/README.md](supabase/tests/README.md), контракт — в [docs/database-contract.md](docs/database-contract.md).

Регистрация закрыта. Пользователи создаются администратором через Supabase Auth; профиль и роль назначаются административно. Тестовые доступы передаются отдельно и не хранятся в Git. Демо содержит двух постановщиков, двух исполнителей, три объекта и шесть активных задач.

Постановщик видит все активные записи, создаёт и редактирует объекты и задачи, назначает исполнителей и принимает результат. Исполнитель видит свои задачи и связанные объекты. Разрешённые переходы:

```text
Новая → В работе → На проверке → Принята
                         ↓
                    На доработке → В работе
```

Возврат требует комментария. Доступ ограничен RLS в базе; изменения выполняются через проверяющие права RPC. Смена статуса и история записываются одной транзакцией. Клиент не может напрямую изменять таблицы или подделывать историю.

## Решения и допущения

- Удаление мягкое: записи скрываются, история сохраняется; удаление объекта скрывает его задачи.
- Постановщики равноправны. Перенос и переназначение задачи сохраняют статус и историю.
- Принятую задачу можно редактировать; повторное открытие не предусмотрено.
- Пустое описание допустимо. Обязательные названия и адрес не могут состоять из пробелов.
- Создание задачи отражается в истории. Изменения текста отдельно не журналируются.
- После действий данные перечитываются; Realtime и архивный экран не предусмотрены.
